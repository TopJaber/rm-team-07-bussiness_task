USER STORIES

US-01. Создание задачи. Как руководитель проекта, я хочу создавать задачу с одним исполнителем и сроком, чтобы задачи не терялись и было четко понятно, кто за них отвечает. Критерий приемки - форма создания содержит поля: "Названия","Срок","Исполнитель", выбрать модно только одного исполнителя. Обработки ошибок - если поля пустые, кнопка "Создать" не работает, выводится ошибка. Связь с требованиями - Создание задач.

US-02. Смена статуса. Как исполнитель, я хочу менять статус своей задачи, чтобы руководитель и клиент видели прогресс без лишних вопросов. Критерии приемки - исполнитель может менять статус только своих задач. Обработки ошибок - при попытке изменить чужую задачу выдается "Ошибка доступа". Связь с требованиями - Жизненный цикл задачи.

US-03. Закрытые задачи. Как руководитель проекта, я хочу закрывать выполненные задачи, чтобы фиксировать завершение работ и убирать их из списка просроченных. Критерии приемки - кнопка "Закрыть" доступна только руководителю проекта, статус меняется на "Закрыта". Обработка ошибок - если исполнитель пытается закрыть задачу - выходит ошибка "Задачу закрывает руководитель проекта".
Связь с требованиями - Права на закрытие.

US-04. Просмотре статуса. Как клиент студии, я хочу смотреть статус задач своего проекта, чтобы не отвлекать менеджера лишними вопросами. Критерии приемки - клиент видит только свой проект, внутренние комментарии и кнопки изменения скрыты. Обработка ошибок - при попытке зайти в чужой проект - ошибка "Доступ запрещен". Связь с требованием - Разграничение доступа.

US-05. Напоминание о сроке. Как исполнитель, я хочу получать автоматические напоминания о приближении дедлайна задачи, чтобы сдавать работу в срок. Критерии приемки - система отправляет уведомления о дедлайне за 24 часа. Обработка ошибок - если у задачи не указан срок, система не сможет отправить уведомление. Связь с требованием - Система уведомлений о дедлайнах.
